## Why this matters

Readme segments are prefixed with literal markers such as `[context: faq answer]`. The system prompt never says to omit them, and the full response is saved. A model that faithfully preserves the source can publish internal metadata in the localized readme.

## Current state

`src/translate.ts:161-165`:

```ts
const templatesWithContext = translatableSegments.map((seg, i) => {
  const ctx = seg.context
  return ctx ? `[context: ${ctx}] ${extracted[i].template}` : extracted[i].template
})
```

At `src/translate.ts:205-208`, the complete returned string becomes `translated`. `ReadmeSegment.context` is already a separate field in `src/readme.ts:3-10`.

## Steps

### Step 1: Make request items structured

Change the readme model input so each item carries source text and optional context in separate JSON fields, or move a position-indexed context list into the system instruction. The translatable `text` field must contain only `extracted[i].template`.

Update the schema/prompt enough that returned translations remain a string array in the same order. Do not require the model to echo identifiers or metadata.

**Verify**: `pnpm typecheck` → exit 0.
